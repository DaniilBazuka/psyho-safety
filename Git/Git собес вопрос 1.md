# 🔍 Как перенести коммиты из одной ветки в другую?
### 1. `git cherry-pick` → перенести **конкретные коммиты**

Используйте, когда нужно забрать только часть работы (1 или несколько коммитов).

bash
```	1. git checkout ветка-назначение 1. 
	 1. git cherry-pick <хеш1> <хеш2>
	    
```

📌Создаёт новые коммиты с теми же изменениями. Если возникнут конфликты:

bash```
```
1.  # Разрешите конфликты в редакторе
2. git add .
3. git cherry-pick --continue
4. или отмените: git cherry-pick --abort
```
### 2. `git merge` → влить **всю ветку целиком**

 📌Стандартный способ объединения веток.

bash
```
1. git checkout ветка-назначение
2. git merge ветка-источник
```

📌 Сохраняет полную историю обеих веток. Безопасно для командной работы
### 3.  `git rebase` → «переложить» коммиты поверх другой ветки

Делает историю линейной

 bash
 ```
 1. git checkout ваша-ветка
 2. git rebase ветка-основа
 ```
### Как выбрать?

| Задача                                             | Команда         |
| -------------------------------------------------- | --------------- |
| Забрать 1–5 конкретных коммитов                    | git cherry-pick |
| Влить ветку полностью                              | git merge       |
| Обновить свою ветку относительно `main`/`dev`      | git rebase      |
| Аккуратно отредактировать/перегруппировать коммиты | git rebase -i   |

💡 **Совет:** Перед операциями, меняющими историю (`rebase`, `--amend`), создайте страховочную ветку:

bash```
```
git branch backup-before-rebase
```
