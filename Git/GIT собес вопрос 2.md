# 🔍 Что такое Merge Conflict?

**Merge conflict** (конфликт слияния) — это ситуация в Git, когда система **не может автоматически объединить изменения** из двух веток, потому что они противоречат друг другу. Git останавливает процесс слияния и просит разработчика вручную решить, какую версию кода оставить.

Это **не ошибка**, а нормальная часть командной работы. Git просто сообщает: «Я не знаю, как правильно объединить эти правки, пожалуйста, решите за меня».

## 🧩 Основные причины возникновения

| Причина                                          | Пример                                                                                              |
| ------------------------------------------------ | --------------------------------------------------------------------------------------------------- |
| **Одни и те же строки изменены по-разному**      | В ветке `main` исправили опечатку в строке 42, а в ветке `feature` полностью переписали эту строку. |
| **Одна ветка удалила файл, другая изменила его** | Вы удалили `old_module.py`, а коллега внёс в него важные правки.                                    |
| **Переименование/перемещение файла**             | В одной ветке файл переименован, в другой — отредактирован под старым именем.                       |
| **Длительное раздельное развитие веток**         | Ветки не синхронизировались неделями → накопилось много пересекающихся правок.                      |
| **Разные настройки форматирования**              | Один разработчик использует `LF`, другой `CRLF` или разные табуляции/пробелы.                       |
## 📄 Как выглядит конфликт в файле?

Git автоматически вставляет специальные маркеры в проблемные участки:
```
	python
		<<<<<<< HEAD
		def calculate_price(item):
			 return item.price * 1.2  # текущая ветка (main)
		=======
		def calculate_price(item):
			return item.price * 1.15 + TAX  # вливаемая ветка (feature)
		>>>>>>> feature-branch
```

- `<<<<<<< HEAD` → начало блока из **вашей текущей ветки**
- `=======` → разделитель
- `>>>>>>> feature-branch` → конец блока из **вливаемой ветки**

## 🛠 Как разрешить конфликт?

1. **Откройте файл с конфликтом** в редакторе
2. **Выберите нужную версию** (или объедините логику вручную)
3. **Удалите маркеры** `<<<<<<<`, `=======`, `>>>>>>>`
4. **Сохраните файл**
5. **Зафиксируйте разрешение:**

bash
```
1. git add <файл_с_конфликтом>
2. git commit -m "Разрешён конфликт слияния"
3. или, если merge ещё не завершён:
4. git merge --continue
```

💡 **Альтернатива:** Используйте встроенные инструменты:

- `git mergetool` (откроет визуальный редактор конфликтов)
- VS Code, IntelliJ, GitHub Desktop имеют встроенные UI для разрешения конфликтов
## 🛡 Как минимизировать конфликты?

| Практика                                                                 | Почему помогает                                                        |
| ------------------------------------------------------------------------ | ---------------------------------------------------------------------- |
| **Часто синхронизировать ветки** (`git pull`, `git merge`, `git rebase`) | Меньше расхождений → меньше пересечений                                |
| **Делать мелкие коммиты**                                                | Легче отслеживать изменения и решать конфликты по частям               |
| **Координировать работу над одними файлами**                             | Избегайте одновременного редактирования `config.yaml` или `styles.css` |
| **Единые настройки форматирования** (`.editorconfig`, Prettier, Black)   | Устраняет конфликты из-за пробелов/переводов строк                     |
| **Использовать feature-ветки + PR/MR**                                   | Код проходит ревью до слияния в основную ветку                         |
